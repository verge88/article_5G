**Протокол:** docs/PHASE7_PROTOCOL.md.

## Объект и условия

Настоящий Open5GS 5G SA и UERANSIM, модель с одним лабораторным UE. SMF во всех трёх фазах продолжает работать. Лабораторный UE выполняет шесть попыток с обычным запрошенным DNN, затем шесть с заранее неподписанным DNN, затем шесть с восстановленным обычным DNN. Параметры рабочей SMF не изменяются. Это штатный сценарий неправильного клиентского запроса, а **не скрытая компрометация**.

Измеряются сообщение UE об исходе PDU, доступность SMF по контейнерному монитору, HTTP/2 NRF discovery, и Nsmf_PDUSession потоковые запросы/ответы, привязанные только через непересекающиеся UTC-окна.

## Полученные данные

| Измерение | Штатный DNN | Неподписанный DNN | Исходный DNN восстановлен |
|---|---:|---:|---:|
| Попытки PDU | 6 | 6 | 6 |
| Успешные PDU | 6 | 0 | 6 |
| Регистрации UE | 6 | 6 | 6 |
| Запущенная SMF | 6/6 | 6/6 | 6/6 |
| SMF присутствует в NRF HTTP/2 Discovery | 6/6 | 6/6 | 6/6 |
| Логические HTTP/2-потоки с Nsmf-запросами | 34 | 2 | 34 |
| Потоки с ответом | 28 | 2 | 28 |
| HTTP 2xx | 28 | 2 | 28 |
| HTTP 4xx | 0 | 0 | 0 |
| HTTP 5xx | 0 | 0 | 0 |

Всего измерено 18 реальных UE-попыток, 70 уникальных потоков с запросами Nsmf и 58 сопоставленных ответов. Из шести попыток в фазе неподписанного DNN **пять вообще не содержали Nsmf-запросов в своём временном окне**; одна содержала два потока с ответами HTTP 2xx без успешной конечной PDU-сессии.

Это подтверждает, что работоспособность SMF и присутствие в NRF не являются гарантиями успешного PDU. Однако одной лишь временной корреляции недостаточно, чтобы точно локализовать стадию отклонения недопустимого DNN. Для этого нужна корреляция действий AMF/UDM/SMF по семантике NAS/SBI и защищённым идентификаторам процедур.

## Проверка научной гипотезы

Наблюдение представляет **обязательный отрицательный контроль** для любого метода поиска скрытой компрометации NF: неуспешная PDU при живой SMF может быть совершенно легитимной. Правило «SMF доступна, но PDU неуспешна => атака» даст на этой лабораторной фазе 6 ложных тревог из 6, если его применять как бинарный детектор компрометации. Это следствие формулировки правила и экспериментальной разметки, а не измеренная оценка FPR в сети оператора.

Значит, метод Data Mining с КИЕ должен включать проверяемые *контекстные признаки разрешённости сервиса* и возможность отклонить гипотезу компрометации при документированном штатном отказе.

## Ограничения

- Реализован **неподписанный DNN тестового UE**, а не неправильный ответ скомпрометированной SMF.
- Один программный стенд, 18 процедур, один UE на фазу, соседние временные окна.
- TCP+HTTP/2 stream ID связывает запрос и ответ внутри соединения, но не доказывает сквозную корреляцию NAS и Nsmf.
- В пяти из шести отрицательных попыток отсутствие Nsmf свидетельствует об ограничении наблюдаемости, а не доказывает конкретный механизм отказа.
- Нет достаточной выборки, чтобы утверждать устойчивость к нагрузке, обновлениям Open5GS или новым абонентским конфигурациям.
- Ни один эксперимент этого этапа не подтверждает обнаружение скрытой злоумышленной компрометации.

## Продолжение анализа

В исходном коде src/phase7_generalization.py предусмотрено внешнее тестирование ранее обученных классификаторов на этом новом **доброкачественном, но ранее не встречавшемся** сценарии отказа. Обучение — отдельное развёртывание Open5GS 101 из четвёртого этапа; калибровка — 202; исходный контрольный тест — 303; проверка ложных тревог — новые измерения с неподписанным DNN. Фальсифицированные отчёты, если используются, создаются программно офлайн и не должны смешиваться с действительно измеренным отказом.

До успешного выполнения соответствующего workflow количественные результаты классификаторов в настоящем отчёте **не утверждаются**.


## Data Mining: проверка переноса модели на новый легитимный отказ

**Воспроизводимый workflow:** https://github.com/verge88/article_5G/actions/runs/38140332799 — успешно завершён.
**Артефакт:** phase7-legitimate-failure-ood-detection (negative_control_fpr.csv, negative_control_metadata.json, зафиксированные версии библиотек, SHA исследовательского кода).

Эксперимент использует независимые первичные измерения Open5GS:
обучение — развёртывание 101, калибровка порога — 202, оригинальный тест — 303, внешний новый тест — успешный стенд этапа 7. Порог фиксирован до нового испытания, классификатор повторно не обучался.

**Первичная исследовательская задача:** выявление искусственно подменённой отчётности NF, а не обнаружение всех отказов PDU. Поэтому все шесть достоверных отчётов нового сценария являются отрицательными примерами, несмотря на отказ PDU по легитимной причине.

| Метод | FPR на исходном штатном режиме (этап 4, 8 попыток) | FPR на неподписанном DNN (6 попыток) | Recall искусственно подменённых отчётов на новом DNN (6 пар) |
|---|---:|---:|---:|
| Random Forest: только локальные признаки | 0% | **100%** | 33,33% |
| Random Forest: локальные + КИЕ | 0% | **100%** | 50,00% |
| Random Forest: КИЕ + признаки NRF/AMF | 0% | **100%** | 100,00% |
| Random Forest + привилегированный Docker | 0% | **100%** | 100,00% |
| Простое правило несогласованности UE–NRF | 0% | **0%** | 100,00% |

**Интерпретация:** все варианты RF на этом малом отрицательном наборе ошибочно распознали допустимый сетевой отказ как фальсификацию отчёта. Причина может быть в выходе новой комбинации признаков (SMF доступна, UE зарегистрирован, PDU не успешна) за распределение обучающих данных; сам эксперимент пока не доказывает конкретный механизм ошибки RF.

Объяснимое правило сверки двух независимых данных не вызвало ложных срабатываний, поскольку честный отчёт UE/NRF не противоречил. Высокий Recall этого правила по искусственным подменам заложен самими условиями их формирования и **не является доказательством обнаружения скрытого нарушения работающей NF**.

Важное ограничение по статистике: результат FPR=6/6 относится всего к шести коррелированным PDU-попыткам одного стенда; доля 100% не должна переноситься на другие версии 5GC, другие DNN, нагрузки или реальную распространённость компрометации.

### Следствие для будущего метода

Отказ PDU при работающей NF сам по себе не доказывает ложность отчёта и тем более кибератаку. Метод с КИЕ должен иметь раздельные уровни:

1. Проверка происхождения и независимости контрольного источника.
2. Проверка семантической согласованности конкретной процедуры с контекстом полномочий и допускаемой причиной отказа.
3. Выявление аномалий по Data Mining только после контекстной проверки, с отдельным состоянием «недостаточно данных» и учётом доли решений.

Следует обязательно сравнивать новый метод не только с RF, но и с прозрачными правилами согласования; иначе научная новизна и измеримый выигрыш останутся недоказанными.
