# Формализация управления КИЕ: два источника, закрытый набор гипотез

## Постановка

В один момент наблюдается неуспешная PDU-процедура UE при разрешённом DNN. В лабораторном эксперименте рассматриваются ровно две конкурирующие гипотезы:

- H_S: SMF остановлена, UPF остаётся запущенной.
- H_U: UPF остановлена, SMF остаётся запущенной.

Это **закрытая лабораторная модель причин**, не реалистичный полный список причин PDU-отказа и тем более не модель кибератаки. В реальной сети возможны отказ AMF/UDM/PCF, неправильный контекст подписки, недоступная N4-ассоциация, перегрузка, неуспешное радиосоединение, повреждение телеметрии и т. п. Если истинная причина вне H_S,H_U, модельная вероятность не имеет калиброванной интерпретации.

## Дополнительные свидетельства

N — Nnrf_NFDiscovery по HTTP/2: регистрируется ли SMF. Реестровый профиль не подтверждает UPF-состояние и фактический PDU-outcome.

U — read-only инспекция порта PFCP UDP/8805 в пространстве имён работающей лабораторной UPF. **Недоступное пространство имён** трактуется как «измерение сокета отсутствует», не как «сокет отсутствует». Привилегированный Docker-running status сохраняется **отдельным полем** как лабораторный oracle. UPF socket сам по себе не подтверждает Established PFCP Association, а Docker state не является доверенным 3GPP свидетельством.

### Энтропия и выбор

Пусть p=P(H_S|E), где E — ранее полученные свидетельства одного эпизода отказа; H(p)=-p log2 p-(1-p)log2(1-p). Условные вероятности отсутствующего сообщения N и недоступности U задаются заранее:

P(N_absent|H_S)=0,9, P(N_absent|H_U)=0,1;
P(U_absent|H_S)=0,1, P(U_absent|H_U)=0,9.

Для кандидата источника K ожидаемое уменьшение энтропии:

IG(K|E)=H(p) - sum_y P(y|E,K) H(P(H_S|y,E,K)).

Эти числа **условные вероятности, заданные проектировщиком**, а не оценённые на новой сети параметры. Для повтора уже опрошенного источника в пределах одного эпизода вводится коэффициент 0,2, отражающий риск коррелированных свидетельств одного и того же NRF/UPF. Коэффициент не калиброван. Промежуточное posterior строится только по подписанному ответу ранее выбранного измерения. Отсутствующий результат не обновляет posterior.

Формальная задача при 4 запросах за 20 попыток UE: выбирать источник K_i∈{N,U} только после наблюдаемого неуспеха PDU, максимум два запроса на один из двух эпизодов, без знания лабораторной метки вмешательства и без будущих UE-исходов.

## Контрольные стратегии

NRF-only: два последовательных N-измерения на эпизод.
UPF-only: два последовательных U-измерения на эпизод.
Mixed: N затем U.
Information: выбрать наибольший предположительный IG с указанным коэффициентом повторения.

**Важная предсказанная до эксперимента слабость:** при симметричных вероятностях и штрафе повторения Information с высокой вероятностью будет выбирать N затем U, то есть совпадёт с Mixed. Поэтому нельзя автоматически заявлять статистический выигрыш нового алгоритма над простым смешанным контролем.

## Строгое и привилегированное определение решаемости

**Строгое** (без использования состояния Docker): N-свидетельство является определённым, если NRF возвращает HTTP/2 200 с измеренным числом SMF либо 404. U-свидетельство является определённым только если пространство имён UPF **доступно** и явно обнаружено присутствие/отсутствие PFCP UDP 8805. Если оно недоступно, следует состояние «неопределено» без принудительного вывода об остановленной UPF.

**Лабораторное oracle-assisted**: дополнительно использовать фактический Docker-running status. Такое решение может иметь высокую полноту, но опирается на привилегированный контроль среды исполнения и не может считаться воспроизводимым независимым агентом внутри оператора.

На этапе 13 проверяется только идентификация одной из двух заранее созданных причин в собственной изолированной лаборатории. Нельзя вычислять или называть полученные результаты Recall обнаружения реальной скрытой компрометации 5G NF.
