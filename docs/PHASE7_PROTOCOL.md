# Этап 7 — отказ PDU-сессии при работающей SMF

## Цель

Экспериментально различить работоспособность сетевой функции и успешность отдельной сервисной процедуры при неизменном работоспособном Open5GS SMF.

## Вмешательство

Меняется только DNN начальной PDU-сессии в конфигурации лабораторного UERANSIM UE:

- Фаза normal: интернет-DNN, для которого подготовлена тестовая подписка.
- Фаза invalid_dnn: намеренно неподписанный DNN с именем lab-unprovisioned-dnn.
- Фаза recovery: возврат к исходному DNN.

Это контролируемая некорректная конфигурация UE, **не взлом, не скрытая атака SMF и не фальсификация отчётов**. SMF не должна останавливаться ни в одной фазе. Если неразрешённый DNN отвергается до обращения к Nsmf_PDUSession, это валидный отрицательный результат для метода мониторинга только интерфейса SMF.

## Средства наблюдения

Используются реальные Open5GS/ UERANSIM и HTTP/2 SBI; шесть попыток каждой фазы. Получаются исход UE (PDU Session Establishment), факт регистрации UE, независимое состояние контейнера SMF, присутствие SMF в NRF Discovery и HTTP/2 Nsmf поток/HTTP-статусы в непересекающихся UTC-окнах.

Открытый артефакт содержит только обезличенные метрики; пакеты, значения IMSI/ключей и содержимое абонентских сообщений не передаются.

## Границы выводов

Наличие NF в NRF и работающий контейнер сами по себе не доказывают успешность PDU-сессии. Отсутствие успешной PDU-сессии при неправильно запрошенном DNN не является доказательством компрометации.

Временная привязка UE и Nsmf не является сквозной идентификацией операции по 3GPP. В частности, 3GPP TS 29.500 уже предусматривает опциональные механизмы корреляции, поэтому сама корреляция не должна объявляться научной новизной.

В дальнейшей работе новизна может быть связана с независимой проверкой достоверности отчёта NF для одной семантически определённой операции, учётом штатных отказов и явной неопределённостью при недостатке надёжных свидетельств.
