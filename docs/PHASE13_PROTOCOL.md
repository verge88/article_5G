# Этап 13: два источника контрольных свидетельств и бюджет информационных КИЕ

**Пререгистрация до новых измерений. 11.10.2026.**

## Исследовательская задача

Проверить, могут ли два отличающихся семантических источника отличить контролируемую остановку SMF от контролируемой остановки UPF при одинаковом конечном наблюдении UERANSIM: разрешённый DNN, PDU не установлена.

## Реальные источники КИЕ

**N:** настоящий HTTP/2 Nnrf_NFDiscovery, число зарегистрированных профилей SMF. Это не доказательство здоровья SMF или завершённости PDU.

**U:** привилегированная, выполняемая отдельным процессом инспекция сети реального контейнера UPF: чтение /proc/net/udp и /proc/net/udp6 с проверкой UDP-порта 8805 (PFCP). Отдельно записывается статус доступности пространства имён и привилегированный Docker runtime state. Если Docker exec не работает из-за остановки контейнера, отсутствие PFCP socket не утверждается: socket_present=null. Наличие сокета не доказывает активную PFCP Association.

Каждый реальный запрос выдаёт отдельную подписанную Ed25519 лабораторную КИЕ с nonce, временем, agent ID и порядковым номером. Самые важные ограничения: два агента работают в одном GitHub runner; подписи не доказывают истинность содержимого; UPF observation требует Docker-привилегий и **не является независимым 3GPP NF API или пригодной для промышленной эксплуатации аттестацией**.

## Новый реальный эксперимент

Три новые изолированные Open5GS + UERANSIM сети на отдельных GitHub runners (один административный домен). Каждая делает 20 настоящих PDU-попыток, по 4 в пяти фазах: normal, upf_failstop, recovery_upf, smf_failstop, recovery_smf. Порядок фаз меняется между средами; восстановления предшествуют следующему контролируемому отказу. Никакие вмешательства не моделируют злоумышленную компрометацию.

Ожидаемые неуспешные PDU не могут быть назначены разметкой эксперимента: читаются только реальные UE-сообщения, результаты Docker доступны для аудита, но не для выбора источника проверки.

## Бюджеты и политики

По четыре **действительных** активных запроса на стратегию в каждом стенде: по два запроса на каждый из двух обнаруженных онлайн эпизодов неуспешной PDU после успешной. Границы эпизода выводятся из наблюдаемого UE status, а не из сценарной метки.

1. N-only: два запроса к NRF на эпизод.
2. U-only: два запроса к UPF namespace /proc на эпизод.
3. Mixed: один NRF, затем один UPF запрос.
4. Information: выбирать источник с наибольшим заранее модельно оценённым снижением бинарной энтропии гипотез H_smf и H_upf. Начальная вероятность H_smf=0,5; условная вероятность верного свидетельства обоих источников эвристически равна 0,9; повторная проверка того же источника дисконтируется фактором 0,2 вследствие зависимости наблюдений. После полученной подписанной квитанции модельное posterior обновляется. Новые результаты не используются для переобучения параметров.

Алгоритмы не получают метку фазы, операторское знание Docker состояния до опроса, будущий UE-исход или незапрошенную NRF/UPF телеметрию. Количество запросов и квоты подтверждает второй независимый *вычислительный* GitHub job, находящийся под тем же администратором.

Если эпизодов меньше двух или восстановление неуспешно, запрещено искусственно считать полный бюджет измеренным. Реальные данные сохраняются как не подтвердившие предпосылки.

## Пререгистрированные показатели

- PDU-success/failure по пяти фазам, состояние SMF/UPF в лабораторном аудите.
- Количество реально выполненных NRF и UPF измерений, HTTP2 latency и размер тел только реальных HTTP ответов, время UPF namespace inspection.
- PFCP socket present / absent / unobservable. **Unobservable не равняется absent**.
- Насколько по доступным свидетельствам различимы H_smf/H_upf; отдельно вывод с привилегированным Docker runtime oracle и без него.
- Покрытие каждого типа отказа, цена КИЕ и доля отказов от уверенного вывода.
- Криптографическая целостность каждой подписи и отклонение replays на другом runner.

## Научные ограничения

Если один лишь NRF уже различает две специально созданные причины, оптимизация выбора второго источника не имеет доказанного преимущества; если Information повторяет Mixed, эффекта ожидаемого информационного выигрыша отдельно не доказано. Предположения о надёжности 0,9 и корреляции 0,2 не откалиброваны. Источник UPF — лабораторная privileged probe, не независимый домен доверия. Отказ NF — штатный контролируемый fail-stop, а не обнаружение реальной кибератаки. Нет гарантии идентифицируемости при работающей, но недостоверно отчитывающейся NF.
