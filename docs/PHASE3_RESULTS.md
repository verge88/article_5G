# Этап 3 — проверенная экспериментальная апробация PDU Session Establishment

**Дата:** 11 октября 2026 г.  
**Исполнение:** [GitHub Actions #38135609531](https://github.com/verge88/article_5G/actions/runs/38135609531).  
**Источник:** результат `real-5gc-pdu-phase3-results` из этого запуска; файлы
`pdu_trials.csv`, `pdu_summary.json`, `sbi_trace_summary.json` и версии контейнеров.

## 1. Реальный стенд и эксперимент

В настоящем Open5GS 5G SA запущены AMF, SMF, UPF, NRF, SCP и
вспомогательные сетевые функции. UE и gNB реализованы UERANSIM, профиль
абонента создан в MongoDB Open5GS. Для всех сценариев использовались
**реальные сетевые функции и реальный сетевой обмен**, а не генератор
признаков из первого этапа.

Каждая фаза содержит три отдельные попытки с новым процессом UE.
Нормальная фаза — SMF работает; фаза отказа — SMF остановлен
посредством Docker в изолированной сети; фаза восстановления —
SMF снова запущен.

**Результаты по журналам UE:**

| Фаза | Попыток | Регистрация UE обнаружена | Подтверждённый успех PDU |
|---|---:|---:|---:|
| Нормальная работа | 3 | 3 | **3** |
| Принудительная остановка SMF | 3 | 2 | **0** |
| После восстановления SMF | 3 | 3 | **3** |

Проверка Docker: при обычной работе SMF, AMF, UPF были запущены;
в фазе отказа SMF подтверждён как остановленный, в фазе
восстановления — как запущенный. В фазе отказа NRF Discovery
не возвращал зарегистрированных SMF на момент контрольных измерений.
Здесь **не наблюдалась устаревшая регистрация SMF**, в отличие от
ранее выполненного эксперимента с AUSF.

Программа опрашивает журналы UE с шагом примерно 2 с. Полученные
временные отметки PDU `2.029–2.033 с` являются **временем до
регистрации успешного сообщения опрашивающим скриптом**, а не точной
сетевой задержкой установления PDU-сессии. Публиковать их как
`PDU Session Setup latency = 2.03 s` некорректно.

## 2. Фактические HTTP/2 SBI-сообщения

Кратковременный пакетный захват TCP/7777 в изолированной Docker-сети
разобран через tshark (HTTP/2). В публичный результат включены
**только безопасные идентификаторы семейств сервисных API**, без
пакетов, IP-адресов и абонентских идентификаторов.

| Семейство SBI | Вхождений заголовка пути |
|---|---:|
| Nnrf_NFManagement | 247 |
| Nsmf_PDUSession | **127** |
| Nnssf_NSSelection | 94 |
| Nudm_SDM | 66 |
| Nudm_UECM | 36 |
| Nausf_Auth | 34 |
| Npcf_SMPolicyControl | 20 |
| Nnrf_NFDiscovery | 9 |
| Другие/неопределённые | 208 |
| **Всего** | **841** |

127 — это количество **вхождений HTTP/2 :path**, а не 127 уникальных
PDU-сессий и не 127 успешных CreateSMContext. Для такой оценки
необходима корреляция с HTTP-методом, кодом ответа и идентификаторами
конкретных диалогов, причём раскрывающие личные данные идентификаторы
в открытом репозитории публиковать не следует.

## 3. Научное значение

Наличие настоящих операций Nsmf_PDUSession и достоверных результатов
регистрации/создания PDU-сессий показывает, что выделить исходные
события и наблюдаемые признаки для KИЕ-мониторинга в работающем 5G Core
возможно. Следующий предмет исследования — не просто регистрация
таких событий, а **проверяемая независимость источников и допустимые
причинно-временные инварианты**.

Набор `pdu_trials.csv` пригоден для воспроизведения инженерной
части, но **не подходит для обучения и оценки Data Mining**: всего
девять экспериментов, нет скрытой подмены телеметрии, нет множества
узлов и зон, нет независимой контрольной выборки и измеренной FPR.
В частности, значения F1 и ROC-AUC из первого синтетического этапа
нельзя переносить на этот стенд.

## 4. Следующие необходимые эксперименты

- Собрать десятки и сотни попыток PDU Session Establishment и их
  временные характеристики в разных условиях нагрузки.
- Извлечь метаданные метода, status, stream ID для реальных
  Nsmf_PDUSession request/response, не публикуя содержимое сессий.
- Отделить временное устаревание NRF при штатных сбоях от устойчивых
  противоречий при намеренной фальсификации контрольных данных.
- Внедрить **отдельный независимый свидетель** в контрольный домен,
  моделировать компрометацию ровно одного из нескольких источников.
- Сопоставить модели только после подготовки независимых train/test
  по запускам и дате/вариантам развёртывания.

**Научный статус:** этап подтверждения возможности реального контроля
SBI/PDU проведён. Доказательства полноты обнаружения скрытой
компрометации в настоящем 5G Core пока **нет**.
