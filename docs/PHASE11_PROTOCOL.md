# Этап 11 — проверка гибридного выбора активных КИЕ на новых реальных 5G Core

**Исследовательская задача:** устранить выявленную на этапе 10 неустойчивость фиксированного порога Random Forest без скрытой подгонки по испытаниям этапа 10 и сохранить ресурс хотя бы для одного наблюдения за состояниями вне обнаруженных отказов.

**Зафиксированный код до выполнения измерений:** GitHub Actions [phase11-prospective-hybrid-vs-baselines](https://github.com/verge88/article_5G/actions/runs/38150830363), исходный commit `b10a93c887bda3136c2963c682b9b9fbd309f3e6`.

## Что было известно заранее

На этапе 10 (реальные 48 PDU-процедур, три runner) в контролируемом сценарии остановки SMF при бюджете по 12 опросов простой контекстный метод проверил 12/12 отказов, периодический 3/12, а RF с прежним фиксированным порогом — 0/12. Следовательно, разработка гибрида учитывала не только опубликованную литературу о сдвиге распределения, но и **результат предыдущего собственного исследования**. Это новое проспективное исполнение, но не полностью независимая постановка научной задачи.

## Новый алгоритм

На очередной фактически завершившейся попытке PDU `i` считаются:
- `S_i=1`, если UE наблюдал отсутствие успешной PDU **при заранее указанном разрешённом DNN**; это *сервисный контекстный триггер*, **не доказательство атаки**;
- `p_i`: вероятность остановки SMF по Random Forest, обученному на предыдущих реальных измерениях из этапов 4/7. Как прежде, метка обучения — **штатный контролируемый fail-stop**, не компрометация;
- `d_i`: флаг выхода времени UE-процедуры или агрегированного счётчика AMF за фактические исторические диапазоны, полученные исключительно из обучающего/валидационного источника (101, 202 и реальные DNN-отказы этапа 7). Это только **эвристический индикатор выхода из диапазона**, не формально калиброванный детектор дрейфа и не гарантия будущего качества.

Четыре стратегии с одинаковым бюджетом **B=4 фактических NRF-опроса на runner**:

1. **fixed** — каждый четвёртый UE-тест, то есть индексы 0,4,8,12.
2. **heuristic** — при `S_i=1`, пока не исчерпана квота.
3. **RF** — при `p_i≥τ`, где `τ` фиксировался по старому развёртыванию 202; новый стенд не участвует в подгонке.
4. **hybrid** — одна **резервная исследовательская проверка** самой первой попытки (индекс 0), затем при `S_i=1`, причём показание RF ниже `τ` не может отменить контекстный сигнал. Для каждого принятого решения сохраняется причина: `exploratory_sentinel`, `model_supported_semantic_priority`, `out_of_training_support_semantic_override` или `below_threshold_semantic_safety_override`.

Если в конце цикла число ещё неиспользованных запросов совпадает с числом оставшихся UE-попыток, происходит **принудительное заполнение квоты**, которое отдельно учитывается, а не приписывается эвристическому/ML-отбору.

**Важная интерпретация:** фактическое правило выбора `hybrid` в текущем сценарии по существу равно семантическому правилу с резервным опросом. Диагностический флаг `d_i` объясняет причину неопределённости, но не даёт самостоятельной доказанной выгоды Data Mining. Поэтому сравнение допускает вывод о полезности семантического переопределения/резерва, **но не об эффективности нового ML-алгоритма**.

## Реальный стенд и изменение условий

Три отдельных GitHub runner получают собственное ядро Open5GS и UERANSIM и выполняют по 16 PDU-процедур: 4 штатных, 4 при неподписанном DNN (исправная SMF), 4 при остановке SMF, 4 после восстановления. Порядки соответствуют предварительно зафиксированным вариантам 11/22/33; тайм-аут фазы остановленной SMF проспективно варьируется: **8, 12 и 16 секунд**. Это управляемая вариация времени ожидания, а не случайная выборка сетевых условий.

Вводы методов — исход UE, факт регистрации, длительность попытки, агрегированные журналы AMF и контекст DNN от координатора. **Методы НЕ получают** заранее известные фазы сценария, Docker-состояние SMF, ответ NRF или результаты будущих попыток.

Агент каждого алгоритма посылает настоящий Nnrf_NFDiscovery SMF через HTTP/2 и возвращает подписанную Ed25519 запись с nonce, порядковым номером, временной меткой и обезличенной статистикой ответа. На другом GitHub job подписи и повторные предъявления квитанций проверяются повторно. Все GitHub runners управляются одним репозиторием и не считаются независимыми административными доменами.

## Предварительно определённые показатели

- Действительное число активных запросов каждой стратегии и проверенные квитанции.
- Доля четырёх реальных PDU-попыток при остановленной SMF, где направлен запрос NRF (знаменатель — 4 на стенд, 12 суммарно).
- Доля опрошенных штатных/восстановленных/неподписанного DNN процедур для оценки *наблюдаемости других состояний*.
- Необходимость принудительно добирать неиспользованный бюджет.
- Суммарная длительность HTTP-ответов и процессов агента, объём **только тел** HTTP-ответов.
- Роль выхода входных признаков за исторический диапазон и причины переключения от RF к семантическому правилу.
- Разделение фактически зарегистрированной в NRF SMF и действительного состояния процесса (Docker только для лабораторного аудита).

## Строго ограниченные выводы

**Не проводятся:** реальная компрометация NF, подмена SBI API, атаки на подпись NRF, работа на независимых административных доменах, несколько одновременно подключённых UE. Успешное подписание КИЕ не доказывает истинность сведений от агента. Опрос происходит **после** завершения попытки UE, а не до отказа сети. Малые повторения и фиксированные блоки фаз не позволяют делать выводы о переносимости на оператора.

В будущем существенным научным результатом мог бы стать алгоритм распределения бюджета, гарантирующий ограничение риска пропуска на независимых доверенных источниках КИЕ; **текущий гибрид таких гарантий не даёт**.
