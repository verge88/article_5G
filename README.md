# 5G Core hierarchical KIE monitoring — reproducible experiments

This repository contains a **synthetic, procedure-inspired experiment** for evaluating whether active Control Information Units (КИЕ / CIUs), zone-level context and independent causal consistency observations improve detection of stealthy SMF-like network-function compromise.

> **Scientific scope:** the generator is NOT a 3GPP-compliant simulator, does NOT execute real HTTP/2 SBI procedures, and does NOT prove production security. Independent witness observations are an explicit trust assumption. A later Open5GS/free5GC testbed is needed for external validity.

## Experiment

- Hierarchy: zones of simulated SMF replicas, each monitored by a zone master; observations from a separate trusted witness are reconciled above the zone.
- Scenarios: normal, legitimate load bursts, signalling DoS and stealthy partial procedure failures with falsified local reports.
- Ablation groups: `local`, `local_temporal`, `plus_kie`, `plus_zone`, `full` (adds cross-observer causal-consistency features).
- Train/validation/test use **disjoint random seeds** to avoid overlapping generated timelines. In-distribution and harder shifted test environments are separated.
- Fixed validation threshold at 1% false-positive rate on benign samples, measured separately on test. Primary outcome: recall for stealth compromise at this operating point.
- Baselines: per-ablation Random Forest, plus unsupervised Isolation Forest on local metrics. Bootstrap confidence interval for the per-seed change in stealth recall.

## Reproduce

```bash
python -m pip install -r requirements.txt
python -m pytest -q
python -m src.experiment --out-dir results
```

The GitHub Actions `research-experiments` workflow runs tests, experiments, and uploads `results/` as an artifact. Its success/failure and downloadable results are visible under the Actions tab.

Data and reported performance are generated by the code, not measured in an operational 5G network. Do not report unobserved improvements or convert synthetic results into field-performance claims.

## Phase 3 — measured real 5G PDU Session Establishment

The [reproducible Open5GS + UERANSIM workflow](.github/workflows/real-5gc-pdu.yml) performs isolated, controlled real-NF PDU establishment trials in three phases (normal, SMF fail-stop, recovery). **All phase-3 evidence comes from actual 5GC/UERANSIM operations, not synthetic traffic.**

The experiment observed 3/3 successful PDU establishments normally, 0/3 while the SMF process was stopped, and 3/3 after recovery. No inference about production intrusion-detection accuracy is warranted from nine procedure trials.

## Phase 4 — actual PDU outcomes, offline falsified monitoring reports

Three separate GitHub-hosted Open5GS/UERANSIM deployments executed 8 normal, 8 SMF-fail-stop and 8 recovery PDU attempts each (72 actual network trials total). Independent HTTP/2 observations included 833 Nsmf_PDUSession path occurrences. The analysis performs deployment-separated train/validation/test and introduces deliberately false *monitoring reports after collection*, not an on-network NF attack.

On the 24-trial held-out deployment, RF local-only detected 16/24 injected lies (FPR 0/24 on truthful twin reports); RF with independent PDU-outcome KIE detected 24/24 (FPR 0/24). Enlarging to additional NRF/AMF or privileged Docker witnesses did not improve recall and produced one false alarm. The apparently perfect 24/24 result is tied to how lies were constructed and does **not** demonstrate effective detection of real compromised NF in production.

## Phase 5 — trust-aware witness reliability (reproducible real-PDU-derived experiment)

[Scientific results and limitations](docs/PHASE5_RESULTS.md) · [GitHub Actions workflow](.github/workflows/phase5-reliability.yml) · [analysis source](src/phase5_reliability.py)

Phase 5 reuses the three separately deployed Open5GS/UERANSIM PDU measurement artifacts from phase 4 (72 real PDU-session attempts). It introduces OFFLINE false, missing, stale and colluding witness observations, and compares local/RF methods with a simple contradiction rule and quorum methods that can abstain when observations are insufficient.

**Key warning:** original PDU events are real, but adversarial manipulation is synthetic and external to the running 5G network. High attack recall in this setup does not establish deployment-grade stealth-compromise detection. Abstention coverage and trust assumptions must be reported alongside FPR and Recall.

## Phase 6 — real HTTP/2 Nsmf/PDU time-window correlation

[Phase-6 verified results](docs/PHASE6_RESULTS.md) | [experimental protocol](docs/PHASE6_PROTOCOL.md) | [existing 3GPP correlation mechanisms](docs/PHASE6_STANDARDS.md) | [GitHub Actions](.github/workflows/phase6-correlation.yml).

Eighteen real UE PDU trials were linked by non-overlapping UTC windows to actual HTTP/2 Nsmf_PDUSession request-response streams, using TCP conversation + HTTP/2 stream ID. The experiment observes successful PDU attempts (6/6 normal, 6/6 recovery) and fail-stop behavior (0/6), along with 213 Nsmf request streams and 206 paired HTTP responses. **This is time-window association, not unique end-to-end procedure-ID linkage, and does not simulate a compromised NF.** The original PCAP is discarded and no subscriber secrets are shared.


## Phase 7 — negative control: healthy SMF, unsupported requested DNN

[Verified experimental report](docs/PHASE7_RESULTS.md) · [experimental protocol](docs/PHASE7_PROTOCOL.md) · [live real-5GC workflow](.github/workflows/phase7-semantic.yml) · [held-out Data Mining workflow](.github/workflows/phase7-generalization.yml).

On a real Open5GS/UERANSIM lab, the SMF stayed running and registered throughout 18 attempts: baseline PDU 6/6 successful, unsupported DNN 0/6, recovery 6/6. At the unsupported DNN, only 2 temporally associated Nsmf HTTP/2 streams were observed (versus 34 for each normal/recovery phase). This is a legitimate UE DNN misconfiguration scenario, **not** compromise.

A previously trained Random Forest-based falsified-report classifier falsely alarmed on all 6 truthful reports under this unseen legitimate failure, despite near-zero FPR on its original held-out conditions. A direct report-to-UE/NRF consistency rule raised 0 alarms. These results are a small experimental negative control, not field estimates or evidence of security against colluding compromised sources.

## Phase 8 — context-aware selective KIE verification and Data Mining

[Verified scientific results](docs/PHASE8_RESULTS.md) · [experimental protocol](docs/PHASE8_PROTOCOL.md) · [source](src/phase8_contextual.py) · [Actions](.github/workflows/phase8-contextual.yml).

The eighth study reuses 90 real Open5GS/ UERANSIM PDU-session outcomes from earlier Actions runs. False NF reports and witness faults are introduced **OFFLINE** and are not real compromised SMFs. Results show a three-valued context-aware policy can improve decision coverage on valid unsupported-DNN denials relative to a strict UE–AMF corroboration policy, without measured FPR change in this tiny laboratory sample. Nevertheless, a simpler direct UE–NRF disagreement rule outperforms it on clean witness data, and colluding corrupt observers invalidate both methods. Data Mining prioritization for undecided reports is evaluated only offline; no active follow-up KIE was sent in phase 8. Read limitations before citing these results.


## Phase 9 — live signed active KIE under a fixed query budget

[Verified research results](docs/PHASE9_RESULTS.md) · [preregistered protocol](docs/PHASE9_PROTOCOL.md) · [trust assumptions and architecture](docs/PHASE9_ARCHITECTURE.md) · [successful GitHub Actions run](https://github.com/verge88/article_5G/actions/runs/38143787757).

In a real isolated Open5GS/UERANSIM lab, 16 genuine PDU attempts were made under normal, unauthorized DNN, controlled SMF stop and recovery conditions. Two Ed25519-signed active NRF discovery poller processes performed exactly 4 real HTTP/2 polls each. An adaptive context heuristic selected 4/4 fail-stop trials for active KIE, compared with 1/4 under periodic sampling, for the same request budget. Eight valid signed receipts and 48 successful rejection checks (field tampering, replay, stale receipt etc.) are preserved with PUBLIC keys but not secret key material.

**Caveats:** both poller processes share the same GitHub runner and trust domain; this is not independent attestation or standard 3GPP authentication, and the experiment does not perform any malicious SMF compromise. Adaptive selection uses a predefined heuristic, not Data Mining, and body bytes are not total network overhead. The results must not be framed as attack-detection Recall or general operator-network performance.


## Phase 10 — reproducible three-runner live KIE budget comparison

[Verified scientific report](docs/PHASE10_RESULTS.md) · [preregistered experiment](docs/PHASE10_PROTOCOL.md) · [successful GitHub Actions](https://github.com/verge88/article_5G/actions/runs/38145977666).

Three separate ephemeral runners hosted genuine Open5GS/UERANSIM networks with 48 real PDU attempts and **36 actually sent, Ed25519-signed HTTP/2 NRF discovery queries**, split equally between fixed, heuristic and pretrained Random Forest schedules. A separate job verified all 36 signatures, nonce orders and all 36 replay rejections.

**Negative research result:** at the same 12-query budget, the simple DNN/UE-context heuristic checked 12/12 controlled SMF stop trials, fixed scheduling checked 3/12, while the frozen-threshold Random Forest checked 0/12. Although prior held-out ROC-AUC was 1.000, the new real stop scores fell below its previously calibrated threshold, causing all 12 ML queries to be fallback quota-filling. This is a **legitimate availability stress test, not attack detection**. Different GitHub runners do not provide separate administrative trust domains; body bytes are not total network overhead.


## Phase 11 — prospective semantic KIE safety override with one exploration query

[Verified results](docs/PHASE11_RESULTS.md) · [experimental protocol](docs/PHASE11_PROTOCOL.md) · [prior art / related work](docs/PHASE11_RELATED_WORK.md) · [successful 3-runner workflow](https://github.com/verge88/article_5G/actions/runs/38150830363).

In three new independent *compute* environments under the same GitHub administrative authority, 48 genuine Open5GS/UERANSIM PDU attempts and 48 actual Ed25519-signed NRF HTTP/2 queries were observed. Four policies consumed 12 queries each. Controlled laboratory SMF fail-stop coverage: **fixed 3/12, contextual heuristic 12/12, frozen Random Forest 3/12, hybrid semantic override + one reserved exploratory query 9/12**. The hybrid queried three non-outage procedures (one per runner); the simpler semantic heuristic retained higher outage coverage. The historical feature-support range flagged more new failures under longer trial timeouts but its independent added utility was not established.

All 48 digital signatures and 48 deliberate replays were rechecked by a separate GitHub Actions job. The experiment **does not** demonstrate malicious 5G NF compromise, trusted independent administrative agents, early outage detection, or a novel calibrated drift-detection algorithm. The current phase is a carefully limited study of *active control allocation under an equal observed budget*.


## Phase 12 — real failure-cause ambiguity: healthy SMF with stopped UPF

[Verified scientific results](docs/PHASE12_RESULTS.md) · [preregistered protocol](docs/PHASE12_PROTOCOL.md) · [original real lab trial data](https://github.com/verge88/article_5G/actions/runs/38154118373) · [successful independent original-data audit](https://github.com/verge88/article_5G/actions/runs/38154732720).

**60 genuine Open5GS/UERANSIM PDU attempts** measured across three isolated runners: normal 12/12 successful, UPF stopped with **SMF healthy** 0/12 successful, UPF recovered 12/12, SMF stopped 0/12, SMF recovered 12/12. The simple authorized-DNN-plus-UE-failure heuristic therefore **cannot infer which NF is responsible**. All available SMF log-count features selected for phase 12 were zero for all 60 attempts; this particular log feature was not informative.

Five strategies sent an equal **12 REAL, signed HTTP/2 NRF queries each** (60 total). Only 3/12 stopped-SMF trials were probed by periodic sampling, 4/12 by the contextual rule, 0/12 by frozen RF, 3/12 by the hybrid, and 4/12 by the SMF-log rule. In 26 NRF queries during **UPF** stop, SMF nevertheless stayed registered in NRF. All 60 receipt signatures and 60 deliberate replays were independently rechecked from the same original artifact data.

**Important reproducibility detail:** all three original network jobs succeeded; the original aggregation job failed due to a pandas variable scoping error. A dedicated auditor with only that code defect corrected then **succeeded on unchanged original ZIP files**. Neither real PDU measurement nor detector decisions were rerun or relabeled for this report. These benign laboratory outages are **not simulated cyberattacks**, and distinct signing processes are not independent administrative trust domains.


## Phase 13 — cross-surface real NRF and UPF PFCP UDP socket KIE

[Verified scientific report](docs/PHASE13_RESULTS.md) · [preregistered methodology](docs/PHASE13_PROTOCOL.md) · [information model and its trust limits](docs/PHASE13_METHOD.md) · [four successful GitHub Actions jobs](https://github.com/verge88/article_5G/actions/runs/38158596155).

Three new disposable Open5GS/UERANSIM deployments completed **60 real PDU attempts**: 36 successes, 12 failures with stopped SMF and 12 failures with stopped UPF. Four equal-budget strategies generated **48 actually executed Ed25519-signed active KIE probes** (24 NRF HTTP/2 Discovery, 24 privileged UPF PFCP UDP/8805 socket observations); all 48 signatures and 48 replay rejections were independently rechecked.

**Important negative finding:** with the two *specific* laboratory fail-stop causes under study, NRF-only produced 12/12 determinate cause labels, while UPF-only produced 6/12; six stopped-UPF socket reads were **unobservable**, NOT evidence of an absent socket. Mixed and presumed entropy-gain information selection both achieved 9/12 determinate labels and **chose identical sources**. No distinct information-optimization improvement was measured. A privileged Docker runtime indicator resolves the remaining cases **only as a lab oracle**, not as independent deployable attestation. UDP 8805 socket presence is not a proven PFCP association. This phase contains no malicious NF compromise.

## Phase 14 — genuine PFCP/N4 service inconsistency with running SMF and UPF

[Pre-registered protocol](docs/PHASE14_PROTOCOL.md) · [Scientific results](docs/PHASE14_RESULTS.md) · [Independent source-artifact audit](docs/PHASE14_VERIFICATION.md) · [Four successful GitHub Actions jobs](https://github.com/verge88/article_5G/actions/runs/38159871173).

Three disposable real Open5GS/UERANSIM 5G Core labs completed 36 UE PDU attempts, with 12/12 normal successes, **0/12 during a controlled SMF network-namespace UDP/8805 PFCP OUTPUT drop**, and 12/12 successes after removal **without stopping either SMF or UPF**. NRF still advertised SMF and UPF still listened on UDP/8805 throughout. Host firewall counters independently counted **253 actually dropped N4 packets** (83, 88, 82), and passive tshark decoded real PFCP Heartbeat/Association Setup/Session Establishment message occurrence counts. A separate runner verified **27 signed KIE and rejected 27 replays**. Raw packet captures and private keys are not published.

**Research limit:** Host firewall counters and UDP captures are privileged lab evidence under one administrative trust domain, not NF-attested PFCP Association and not indicators of deliberate stealth compromise. PFCP capture frame occurrences are not unique UE sessions. These results establish a concrete operational counterexample to endpoint-status-only NRF/UPF KIE health checks.
